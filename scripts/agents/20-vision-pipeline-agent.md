# 智能体：视觉流水线（采集 / 识别 / 测距）

## 角色

负责 `src/capture`、`src/detect`、`src/stereo`、`src/fusion`、`src/app` 的正确性与性能。

## 所有权

可写：`src/capture/**`、`src/detect/**`、`src/stereo/**`、`src/fusion/**`、
`src/app/**`、`src/common/**`（共享文件改动需先与界面智能体打招呼）。

不要改：`src/ui/**`、`scripts/**`（需要构建变更时提给构建智能体）。

## 输入

- 现象：帧率、延迟、距离是否合理、哪些目标测不到；
- 观测数据：`scripts/run_board.sh headless` 的输出、`out/` 里的截图与 `stats.jsonl`。

## 输出

- 改动后的流水线代码 + 变更说明（改了什么、预期提升多少）；
- 无相机时的自测证据：`--image-pair` 跑参考双目图，距离随视差单调、目标数稳定；
- 性能数字：采集/识别/测距 fps、推理 ms、测距 ms、端到端 ms。

## 硬约束（违反会直接变慢或崩溃）

1. 测距只用目标级 ROI SGBM：水平范围 = 框宽 + 视差范围（必须留够搜索范围），
   垂直 ≤128 行；不要退回整幅稠密匹配。
2. `cv::setNumThreads(1)`，并行只由线程池负责（默认 6 线程）。
3. 模型的 letterbox 必须与 `rknn_model_zoo` 对齐（%4/%2 对齐 + 居中填 114）。
4. 量化模型不要打开 `want_float`（反量化会白吃 CPU）。
5. 遍历容器的同时禁止 `push_back`（GCC 7.5 -O3 会生成错误代码）。

## 完成判据

- `--image-pair` 自测：13 个目标全部有距离或明确的无效原因，数值跨帧稳定；
- 真实相机：采集 30fps 时测距不成为瓶颈（无目标场景整链 30fps）；
- 改动前后给出同一场景的对比数字。
