## 4. 测距优化前后对比（同一组 13 目标）

| 方案 | 单帧测距耗时 | 测距帧率 |
|---|---|---|
| 全宽横带 + 4 线程（初版，OpenCV 内部默认 8 线程造成超订） | 770 ms | 1.2–1.9 fps |
| 窄 ROI（框宽 + 视差范围）+ 6 线程 + OpenCV 单线程 | **44 ms** | **14.0 fps** |

优化要点：把 ROI 从“整幅宽度”缩到“目标宽度 + 视差范围”，并把 OpenCV 内部线程数
压到 1，避免 6×8 线程互相抢核（超订时反而慢一个数量级）。

## 5. 界面验证

- 通过 SSH（`DISPLAY=:0`）启动 `eye_range`，进程稳定运行，流水线正常输出 30fps。
- **全屏验证**：`xwininfo -root -tree` 显示窗口几何 `1024x768+0+0`，与屏幕尺寸一致，
  即真正全屏、无标题栏、无留白溢出（显示器为 1024x768）。
- `gnome-screenshot` 抓屏分析：左侧视频区有明显图像内容（灰度均值 91–112/标准差 76–82），
  右侧面板区域存在控件与视差/深度画面（均值 161/标准差 101.7），确认 Qt 界面在板上真实渲染。
- Qt 报 `libGL: failed to load driver: rockchip` 属正常现象：QWidget 走软件光栅渲染，
  不由 GL 驱动参与，界面功能不受影响。

## 7. 双目标定实测（棋盘格 9x6 内角点，格长按 25mm）

远程辅助流程：取景器全屏实时显示棋盘检出状态并自动存图 → 稳健解算（统一 SB 角点检测 +
逐视角误差剔除）→ 极线对齐自检。

| 指标 | 数值 |
|---|---|
| 采集图像对 | 58 对（其中 2 对 SB 检测失败被自动跳过） |
| 参与解算视角 | 56 |
| 单目 RMS | 左 0.239 px / 右 0.233 px |
| **双目 RMS** | **0.412 px** |
| 基线 | 65.23 mm（T = [-65.23, -0.15, 0.59]，y/z 分量≈0，符合水平双目） |
| 左目 fx/fy/cx/cy | 859.3 / 859.0 / 609.8 / 492.5 px |
| 右目 fx/fy/cx/cy | 864.1 / 863.6 / 678.4 / 489.8 px |
| 校正后 fx | 956.02 px |
| 距离公式 | `Z[m] = 62.36 / 视差[px]` |
| 极线对齐误差 | 平均 0.266 px，最大 1.51 px（校正正确） |

由该标定推算，采集时棋盘格距相机约 0.25–0.53 m（手持距离，合理）。

> **尺度提醒**：`Z ∝ 棋盘格真实边长`。上表按 25mm 格长计算；若实际格长不同，
> 用 `真实格长 = 25mm × 实测距离 / app 显示距离` 修正后重跑
> `eye_range_calib calibrate --square <真实格长>` 即可（不需要重新采集图像）。

标定文件：`config/calib.yaml`（已同步回本机工程）。

## 8. 界面稳定性复测（2026-10-09 更换电源后）

背景：换电源前“一跑界面就整机硬重启”（详见 `doc/06` 第 8~10 节）。
更换电源后用 `scripts/run_stress.sh` 带监控复测，**问题消失**：

|---|---|---|---|---|
| 无边框铺满，满配 | 300 s | 5.17 | 67.5°C | **未重启** |
| 真全屏，满配（合成器开启） | 180 s | 5.59 | 66.5°C | **未重启** |
| 默认配置（真全屏）+ 截图 | 50 s | — | — | 窗口 1280x960+0+0，正常退出 |
| 无界面，满配 | 260 s | ~2.9 | 56°C | 未重启（换电源前同样稳定） |
