# 07 项目说明

> 最后更新：2026-10-09（更换电源后复测通过）

## 一、这是什么

`eye_range` 是在 **OrangePi 5 Max（RK3588）+ DECXIN 双目相机** 上运行的双目视觉测距工程：
双目采集(V4L2/MJPG) → NPU 上跑 YOLOv8 识别目标 → 对每个目标做立体匹配测距 → Qt 全屏界面显示。

本机（WSL）交叉编译，产物传到板子上运行；板上只用系统自带的 OpenCV / Qt / RKNN 运行时。

## 二、当前状态

| 项目 | 状态 |
|---|---|
| 采集 / 识别 / 测距 | ✅ 已实现并在真机验证（30fps 采集、推理 ~20ms、测距 24~60ms） |
| 双目标定 | ✅ 已完成，双目 RMS 0.412px，基线 65.23mm（棋盘格按 25mm 计） |
| Qt 全屏界面 | ✅ 默认真全屏（窗口 1280x960+0+0），含参数热调、视差/深度图、快照 |
| 稳定性 | ✅ 换电源后满配连续运行 5 分钟无重启（负载 5.17、67.5°C） |
| 距离绝对精度 | ⚠️ 未用卷尺核对；棋盘格实际边长需确认（距离与该值成正比） |

## 四、常用命令

```bash
# 项目管理入口（先跑这个）
scripts/manage.sh overview && scripts/manage.sh check

# 一次性：从板上同步 OpenCV 到本机交叉 sysroot
scripts/bootstrap_sysroot.sh

# 编译 + 部署
scripts/build_aarch64.sh
scripts/deploy_board.sh

# 运行
scripts/run_board.sh sysinfo          # 环境自检（版本/相机/NPU/模型）
scripts/run_board.sh ui               # 全屏界面（板子显示器）
scripts/run_board.sh headless 60      # 无界面，截图与统计写到板上 out/
scripts/run_board.sh calib-capture    # 标定采集
scripts/run_board.sh calib-solve      # 标定解算

# 压测 + 日志自动归档到 logs/
APP_TIMEOUT=300 scripts/run_stress.sh borderless
APP_TIMEOUT=180 scripts/run_stress.sh fullscreen --fullscreen
APP_TIMEOUT=300 scripts/run_stress.sh headless --headless --duration 300
```

## 五、实测性能

| 场景 | 采集 | 识别 | 测距 | 端到端 |
|---|---|---|---|---|
| 真实相机 2560x960，无目标 | 30 fps | 30 fps（推理 18~23ms） | 24 ms | 30~56 ms |
| 离线双目图 13 个目标 | — | 20 fps | 44 ms | 147 ms |
| 换电源后满配界面 5 分钟 | 30 fps | 30 fps | — | 稳定（负载 5.17、67.5°C） |

距离公式 `Z[m] = 62.36 / 视差[px]`（fx=956.02px、baseline=65.23mm，按 25mm 格长）。
视差上限 128 → 最近可测约 0.49m；5m 处 1px 视差误差约 8%。

## 六、已知问题与注意事项

1. 供电是第一优先级。早期“一跑界面就整机硬重启”的根因是电源不足：
   换电源前负载仅 1.5 也会重启、且没有任何内核日志，属于电源瞬态跌落导致 SoC 复位；
   换电源后同样配置（负载 5.17）稳定。现场请用 5V/4A 以上 DC 供电，
   不要用电脑 USB 口或手机充电头。详见 `doc/06` 第 8、9 节与 `logs/`。
2. 距离尺度：棋盘格实际边长若与 25mm 不符，用
   `真实格长 = 25 × 实测距离 / 界面读数` 修正，再跑
   `eye_range_calib calibrate --square <真实格长>`（不必重新采集图像）。
3. 相机对着白墙等无纹理场景时，检测为 0、视差大面积无效，属正常现象。
4. 显示器 EDID 上报尺寸为 0mm（1280x960@60）；如遇显示异常优先换 HDMI 线。
5. `--low-power`：供电/散热余量紧张时使用（NPU 单核 / 2 线程 / 15fps 采集 / 12fps 界面）。

## 七、关键设计（为什么这么做）

- 单设备左右拼接：DECXIN 双目在 `/dev/video0` 输出 2560x960（每目 1280x960），
  按中点切分即可，硬件已同步。
- NPU 直出量化结果：不开 `want_float`，省掉每帧百万级 float 转换。
- 目标级窄带 SGBM：ROI 宽度 = 目标框宽 + 视差搜索范围（保证测距上限），
  高度不超过 128 行，多目标并行 4 线程，`cv::setNumThreads(1)` 避免超订。
  相比整幅稠密匹配提速 17 倍（770ms → 44ms）。
- 三线程流水线：采集 → 识别(NPU) → 测距(多核)，用“最新帧槽”覆盖式传递，
  界面始终显示最新画面。
