# 01 需求与方案设计

## 1. 需求

在 OrangePi 5 Max（RK3588）+ 双目相机上实现：

1. 双目采集 → YOLO 识别（给出类别 + 框）→ 对识别目标做双目测距；
2. 用上 RK3588 的 8 核 CPU 与 NPU（3 核）提高识别帧率与测距速度；
3. 可视化界面用 Qt；
4. C++ 工程，本机交叉编译，产物传开发板测试；
5. 实际画面人工辅助测试；
6. 目录约定：`doc/` 过程文档、`skills/` 脚本与技能、`scripts/` 智能体、`src/` 源码、`build/` 编译产物。

## 2. 结论：为什么这么设计

### 2.1 相机：单设备左右拼接

实测相机为 DECXIN UVC 双目模块，**一个设备节点输出左右拼接帧**（`/dev/video0`，
MJPG 2560x960 = 每目 1280x960 @30fps）。因此采集侧只需要一个 V4L2 句柄，
拿到整幅后按中点切分左右目，不需要两路同步（硬件已经同步）。

### 2.2 识别：RKNN + NPU

- 模型：YOLOv8n（COCO 80 类），`model/yolov8.rknn`，输入 640x640，int8 量化。
- RKNN C API 直接推理，**不做 want_float 反量化**（量化输出直接解码），省掉每帧
  约 100 万个 float 的转换开销。
- 解码逻辑对齐官方 `rknn_model_zoo/examples/yolov8`（DFL + 3 分支 + 可选 score_sum 预过滤）。
- 支持 NPU 核绑定（AUTO / NPU0 / NPU1 / NPU2 / 三核），运行期可切换。

### 2.3 测距：目标级窄带 SGBM（本项目的关键优化）

朴素做法是每帧对整幅图做 SGBM 稠密匹配，RK3588 上 1280x960 + 128 视差约 300ms/帧，
完全不可用。本项目的做法：

1. 只对**检测框附近**做匹配（`roi_only=1`）；
2. ROI 水平方向裁剪为 `[box.x - nd, box.x + box.w]`：**必须给目标区域留出完整视差
   搜索范围**，否则窄 ROI 会把可测距离上限压得很低（例如 100px 宽 ROI 只能测到 0.5m）；
3. 垂直方向只取目标中心附近的若干行（默认 ≤128 行），计算量随带宽线性下降；
4. ROI 面积过大时内部降采样，视差最后折算回全分辨率像素；
5. 多个目标用线程池并行（默认 6 线程），**并把 OpenCV 内部线程数压到 1**，
   避免与线程池抢核（8 核被 6×8 线程抢占时反而慢 10 倍以上）；
6. 距离 = `fx * baseline / (disparity - doffs)`，取框内中心区域有效视差的**中值**，
   再由 `DistanceFilter` 做 IoU 关联 + 时间平滑（EMA + 滑动平均）。

实测：1762x800 参考图、13 个目标的场景，测距从 770ms/帧降到 44ms/帧。

### 2.4 线程模型

```
采集线程  ──最新帧槽(覆盖式)──►  识别线程(NPU)  ──最新结果槽──►  测距线程(CPU多核池)  ──►  发布结果
  30fps                         ~20ms/帧                        6 线程并行 ROI           共享指针给界面
```

- 三个“最新值槽”（`LatestSlot`）都是**覆盖式**的：处理慢了就丢旧帧，不排队，
  保证界面看到的永远是最新画面（实时性优先于不丢帧）。
- 界面/无界面主循环只读取最近结果，不阻塞流水线。

### 2.5 界面

Qt5 Widgets，左侧视频（带框 + 类别 + 置信度 + 距离），右侧视差图 / 深度图 / 参数 / 状态。
参数可运行期热改（置信度、NMS、NPU 核、ROI 开关、并行线程、视差范围、块大小）。
